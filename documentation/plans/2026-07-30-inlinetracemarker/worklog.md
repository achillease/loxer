| 2026-07-30 01:50 | [Implementation] Decision: arrows read their own parameters | An arrow has no `arguments`, and wrapping it in a rest-parameter wrapper — the statement form's answer — would move the options expression out of the scope it was written in, where it can read the arrow's parameters. A destructuring parameter cannot be read as a whole, so it is exchanged for a generated name and re-declared as `let <pattern> = _traceArg;` above the traced body: `Function.length` does not move (a name and a pattern each occupy one parameter), `let` keeps a reassignable parameter reassignable, any type annotation moves onto the generated parameter, and the bindings stay in the scope the options and the body both read them from.
